# SRS – API Gateway с порталом упаравления API

## 1. Функциональные требования

| ID | Требование | Приоритет |
|----|------------|-----------|
| FR1 | Динамическая маршрутизация запросов к микросервисам | High |
| FR2 | Аутонетефикация через OAuth 2.0 / JWT / API Keys | High |
| FR3 | Rate limiting (oграничение запросов) | High |
| FR4 | Сircut breaker (защиа от большого количества отказов) | Medium |
| FR5 | Логированиевсех запросов и ответов | High |
| FR6 | Автоматическая генеация документации из OpenAPI | High |
| FR7 | Панель монтиринга (задержки ошибки и тд) | Medium |
| FR8 | Управление API-ключами пользвателей | Medium |

---

## 2. Нефункциональные требования

| ID | Требование | Значение |
|----|------------|----------|
| NFR1 | Время отклика запроса (geteway overhead) | < 10 мс |
| NFR2 | Пропускная способность | 1000 RPS |
| NFR3 | Доступность (SLA) | 99.9% |
| NFR4 | Покрытие тестами | > 70% |
| NFR5 | Логирование | все запросы с метриками |

---


## 3. Технологический стек
- API Gateway: Kong / Node.js + Gateway
- Аутентификация: OAuth 2.0, JWT
- Кэш и лимиты: Redis
- Документация: Swagger UI (OpenAPI 3.0)
- Оркестрация: Docker + Kubernetes 
- ТестыȘ pytest / Jest + Supertest
